Web security

How websites get attacked and how developers prevent it.

What you will learn

  • Describe SQL injection and XSS
  • Explain why input must be validated
  • Know the OWASP Top 10

Never trust input

Anything a visitor types, or a browser sends, may be hostile. Applications must validate it and encode it on output.

SQL injection

If a site glues user text into a database query, an attacker can change the query. The fix is parameterised queries, which keep data separate from commands.

Cross-site scripting (XSS)

XSS happens when a site shows untrusted text as HTML, letting an attacker run JavaScript in other visitors' browsers. Output encoding and a Content Security Policy reduce it.

OWASP Top 10

OWASP publishes a list of the most common web risks. It is the standard starting point for web security study.

Key terms

  • Injection: Untrusted data treated as commands.
  • XSS: Attacker script running in a victim's browser.
  • CSP: Header limiting which scripts may run.
