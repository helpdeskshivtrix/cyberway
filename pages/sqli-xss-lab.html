SQL injection & XSS playground

A self-contained, fake vulnerable mini-app. Nothing here touches a real database or server — it's all simulated in your browser so you can learn the patterns safely. Never try these techniques against systems you don't own or have explicit written permission to test.

Fake login form — SQL injection

This simulated login naively builds a query like SELECT * FROM users WHERE username='<input>' AND password='<input>' without sanitizing input. Try to log in without knowing a real password.



Need a hint?


The query becomes ... AND password='' OR '1'='1'. Since '1'='1' is always true, the condition passes regardless of the real password. The fix: parameterized queries / prepared statements, never string-concatenated SQL.







Fake comment box — Cross-Site Scripting


This simulated comment box can render your input as raw HTML inside a sandboxed, script-blocked preview frame — the same mistake that lets attackers inject scripts into real pages.



 




Need a hint?


The "unsafe render" drops your text straight into the page's HTML, so a tag like <img onerror=...> would run. The "sanitized render" escapes special characters first, so the browser shows the tags as plain text instead of running them. Always escape or sanitize user input before rendering it as HTML.
